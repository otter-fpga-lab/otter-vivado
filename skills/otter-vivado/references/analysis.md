# 采样证据、分析假设与下一轮取证

本插件提供分析入口与工作方法。消费者的协议、状态编码、假设、报告和页面由智能体
结合该工程生成；不要把某个工程的阈值、RTL 名字或诊断结论写死在插件。
先读 [波形数据](waveform.md)，需要设备动作时读 [硬件调试](hardware-debug.md)。
完整输入/状态语义见源码根 `docs/ILA_ANALYSIS.md`，以实际 MCP schema 为准。

## 先固定问题与证据

1. 从用户目标及消费者工程发现要验证的具体问题，例如“背压期间 payload 是否改变”。
   读取已有设计说明/RTL 和探针目录，写出预期行为及依据，不从信号名猜协议或状态编码。
   保存假设、已知事实、未知条件；没有语义时先统计，不生成看似确定的协议结论。
2. 保留原始 VCD、导出 manifest、会话/目标/核身份，以及采集前后的共享快照和触发配置。
   记录输入 SHA256；不要用“最近导出的文件”代替身份核对。已有数据足够时先分析。
3. `read_ila_waveform(...,signal_ids=[])` 取得目录，将 VCD id、scope/name/width 与
   工程语义建立显式映射。sample_clock 的边沿、before_tick/after_tick、复位有效电平
   必须来自工程证据。ILA 没有可观察的时钟边沿时，不能把 tick 擅自当成采样时钟。

## 执行有限、可复核的检查

在消费者工程保存 spec.json，调用 `analyze_ila_capture(file_path,spec,...)`，传入原始
文件 SHA256，保存 analysis.json。支持统计、allowed_values、state_transitions 和
stable_while_stalled；不执行用户脚本，也不是 AXI/UART/SPI 等全协议解码器。

- 统计可用于定位不变化、未知值或异常范围；不变化本身不等于卡死，无符号范围不等于
  定点/有符号物理量。根据已确认编码解读，单位未知就保留 tick/原始值。
- violated：用 source SHA、规则名、tick、原值/前值展示反例；先核对映射、取值时机和
  规则是否正确，再提出设计问题假设。不能把“违反声明”直接当成已证明的 RTL 根因。
- inconclusive：指出缺少哪种证据，不能写 PASS。零有效检查、时钟歧义、未知值、未知
  复位、请求超出文件都可能导致此状态。状态机不能跨复位或未知值拼接出一次跳转。
- consistent：只说明所选窗口和规则内一致。握手 pending_at_end=true 时仍缺完成证据；
  本工具没有死锁/活性证明。只做统计的 observed 也不能当成测试通过。
- blocked：处理具体格式、输入或资源限制。超事件数就缩小窗口/信号，不抽点后声称检查
  了所有边沿。返回证据例子有限但计数完整，查看 evidence_truncated；可缩窗查其它反例。

## 选择下一轮条件并执行已授权步骤

把 next_capture_suggestions 当作取证目标，不当作可直接执行的命令。生成消费者计划，
写清关联假设、上一份文件指纹、应补什么证据、信号范围、触发/深度/前后窗口和停止条件。

| 证据情况 | 下一轮优先验证 |
| --- | --- |
| 已有确定反例 | 保留该反例前态和后果，扩大触发前窗口；先核对取值时机，再改一项条件 |
| 状态跳转异常 | 核对真实状态编码、复位和前态；按实际支持的比较器捕捉相关状态 |
| 等待期间数据变化 | 捕捉 valid/ready/data 与明确时钟/帧标记；不要把复合时序规则伪装成单探针 eq 条件 |
| 时钟缺失、x/z 或映射不明 | 核对导出和 probes 来源、时钟与采样条件，补证据；不设置“匹配 x”触发来掩盖未知 |
| 末尾仍等待、没有有效检查 | 扩大相关上下文或改取证事件；ILA 深度不等于能连续观察几秒钟 |
| 当前规则一致 | 保留窗口与适用范围；只有任务还需其它场景时才继续采集 |

执行前从共享快照核对设备/核 UUID/实际 hw_probe 名、宽度、CONTROL 和 supported trigger
语义；VCD id 不是 probe 名。使用已有 `debug_action` 的 revision/控制权/操作回执，在
用户已经授权的调试范围内逐步 configure、arm、确认完整、export 到新目录。不因每轮
分析而重复要求批准；新的设备写入范围无法从授权确定时才补充信息。未知回执先核对实际
状态，不自动重试或重新采集来“修复”证据。控制权交回人工后停止写入。

复杂触发超出现有入口时，说明具体缺口，先给可执行的较小取证方案；不要编造硬件支持，
也不绕过共享服务另开进程争抢目标。需要本地就绪、倒计时和动作标记时接续 [实验参考](experiment.md)。
时序精确配合需要 FPGA 事件/帧编号，浏览器和聊天
往返不是触发时钟。需要改业务 RTL 时沿用 Coding 产品职责。

## 报告与消费者可视化

每轮报告连结原始 VCD、manifest、spec.json、analysis.json 和触发快照。报告依次写：
观察到的事实、规则结果与引用 tick、可能解释及反证、尚缺证据、下一步或停止理由。
保留旧规则；修正规则后生成新的 spec 指纹，不能覆盖旧记录制造“已经通过”。

可视化由智能体放在消费者工程，复用 [生成指引](visualization.md)：反例列表点击后定位
原波形窗口，展示前后值和证据不足提示；统计、用户假设和工具验证结果分别标明来源。
不把推测画成已测数据，不在本库新增固定分析仪表盘。合成样本标 demo，软件测试与
真实 EDA/板卡结论分开交付。
