# 为消费者工程生成可视化

本插件给智能体提供能力和做法：根据真实状态、报告和工程语义生成可视化。最终页面由
智能体在消费者工程中生成并维护。库内 `web/` 是可选参考，不是消费者必须使用的界面，
也不应该成为所有项目共用的布局或主题仓库。

## 选择页面要解决的问题

1. 先读消费者项目说明、已有页面风格和当前任务。确认要展示的是构建进度、报告对比、
   文件交付证据还是板上控制；仅按当前目标取数据，不默认生成全功能仪表盘。
2. 在消费者目录（例如 `debug-ui/`）保存页面、适配代码、数据样例和启动说明。
   优先沿用项目技术栈。视觉布局、配色、单位、控制范围和实验步骤属于消费者。
3. 记录每个展示值的数据字段、单位、来源、采样时间以及未知条件。示例数据显式标记
   demo；缺少实测值就显示未知，不能用随机曲线、假进度或默认零代替。

## 复用能力，不复制 Vivado 执行逻辑

| 页面需求 | 数据/操作来源 |
| --- | --- |
| 运行状态和报告 | `get_run_snapshot` / `get_run_progress`；保留 session、run、目标阶段与来源 |
| 调试交付检查 | `export_debug_bundle` 的结果、manifest 与 `check_debug_artifacts` JSON |
| 调试控制与状态 | 同一个 `DebugService` 的 `snapshot()` / `submit()`，或已连接的 MCP 入口 |
| 波形/采样分析 | `debug_action(export_ila)` 导出 VCD；`read_ila_waveform` 提供事件，见 [波形参考](waveform.md) |

静态交付页面可以读取保存的 JSON，完整展示文件 SHA256、检查状态和未验证项，无需
启动 Vivado 或网页后端。不要将 `exported`、`consistent` 或 `record_matches` 显示成
“板卡验证通过”或“时序通过”。

实时页面需要消费者本机适配层，复用库内 Python 服务及实际 MCP schema。当前内置
HTTP 服务只服务自己的参考 HTML，**没有任意 HTML 加载或跨站调用接口**；不能只写一个
HTML 然后声称它已经接入。若采用 Python 集成，在服务所属 asyncio 循环中调用
`DebugService.submit(request, source="manual")`；`snapshot()` 可读共享缓存。
适配层只接受固定动作，不提供任意 Tcl/命令执行。沿用回环监听、同源写入和实际操作回执。

同一实际 session 只维护一份调试服务；消费者适配与 AI 必须共用该服务实例或明确的
同一服务入口。另起 CLI/MCP 进程不会自动共享 revision、控制权和操作历史。不要靠
多开连接伪造“人机共用”；无法接入现有服务时，先把集成限制写明，保留只读展示。

## 控制行为与验收

- 设备、核、探针使用完整发现名称。写入使用实际位宽/方向与消费者定义的取值范围。
  宽整数通过十进制或十六进制字符串传输，避免 JavaScript 数字丢精度。
- 提交携带最新 revision；保存 operation_id，显示最终 succeeded/failed/unknown。
  busy 或过期请求提示刷新，不排队自动重放；unknown 需核对实际状态。
- 人工/AI 控制权、失联、数据时间和错误必须可见。浏览器控件即时反馈走本机服务，
  不让每次滑杆变化依赖模型回复，也不把浏览器计时当作 FPGA 精确触发。
- 实际验证桌面/窄屏、键盘操作、缺失数据、失联和错误展示。交付页面路径、启动方法、
  连接入口及数据来源；演示能打开与真实 EDA/板卡通过分别记录。

已有 slider/toggle JSON 只是参考页的一种便捷配置，不定义所有消费者页面的视觉能力。
后续曲线、布局和实验交互继续由智能体生成；本库只补必要的数据和操作接口。
